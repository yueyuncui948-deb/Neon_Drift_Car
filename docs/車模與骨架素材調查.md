# 選車系統：車模與骨架素材調查

調查日期：2026-10-14（Asia/Taipei）。本次完成資料調查與檔案檢查，**尚未把外部車模加入遊戲，也尚未實作選車介面**。下載供研究的檔案放在暫存區；Git 保存來源、版本、授權與檢查結果，不把未確認的素材帶進正式遊戲。

建議先採用 **Quaternius Cars Pack 的低多邊形車款**作為美術候選，並以 **Kenney 官方範例中的 4 台車**驗證選車與輪軸轉接流程。Quaternius 原檔尚未成功下載，不能宣稱已驗證骨架；Kenney 4 台已成功匯入 Godot，但屬卡車造型，較適合作為系統開發素材。

## 賽車一定需要骨架嗎？

不一定。車身、四輪、方向盤、車門等剛性零件，可以透過獨立節點及正確旋轉中心操作。車輪滾動／轉向、懸吊上下移動，都不必先做角色式蒙皮。選車系統真正需要的是一致的模型介面、尺寸與操作設定，而不是每台車都附有大型控制骨架。

只有在確實需要蒙皮變形、既有骨架動畫或特定製作流程時，才使用骨架。Blender 的控制器、約束、驅動器不會全部直接變成 Godot 的遊戲控制；通常需整理為簡單的匯出骨架，烘焙動作並驗證匯出結果。

目前原創 ION-01 仍由 `tools/build_car.py` 的 `bpy` 程序生成；四個 Empty 輪軸不是骨骼，沒有外部骨架。這項來源紀錄沒有改變。

## 骨架製作工具

[**Rigacar 7.1**](https://github.com/digicreatures/rigacar/tree/f25da074279ac9c59d72e05c4f457015d6bb2dd1)由 David Gayerie 製作，可生成車輛骨架、處理車輪動畫與烘焙。這是工具，不是含大量車款的模型包。

- 原始碼授權 GPL-3.0-or-later；輸入的車模仍須有自己的使用授權。
- 外掛 `bl_info` 宣告 Blender 2.83；本次未在 Blender 4.3.2 安裝或執行，不能宣稱相容。
- 若後續採用，必須記錄外掛版本、輸入車模來源，以及哪些骨骼由工具生成。
- 遊戲端宜保留必要的車身／車輪／懸吊／車門骨骼，測試匯出後的變換及動畫；無須把全部製作用控制骨骼帶入遊戲。

## 建議的選車素材規格

先做 3–5 款風格一致、可實際駕駛的車，再擴充素材庫；大量下載不同規格車模會增加轉接成本。

1. 每款保存穩定 `vehicle_id`、作者、原始網址、授權、來源版本、下載日期及 SHA-256。車身塗裝與車款分開記錄。
2. 用轉接場景統一車頭方向與米制尺寸，映射車身、四輪節點及半徑。Kenney 使用 `wheel-front-left` 等命名；現有 ION-01 使用 `Wheel_FL` 等命名，不能僅換 GLB 就假定動畫可用。
3. 選車資料分開保存顯示名稱、模型場景、預覽圖、輪軸路徑、碰撞尺寸、速度／轉向／氮氣參數；控制器共用。
4. 建議起始預算為每車約 2,000–8,000 三角形、少量共用材質；這是本專案的設計目標，需以實機結果調整，不是 WebGL 的硬限制。
5. 僅載入正在展示與使用的車；顏色差異用共用模型加材質變化。高面數車先做 LOD，檢查透明、透射、清漆等材質在 Compatibility 的實際表現。
6. 驗收車頭方向、四輪位置及正反轉、轉向中心、落地碰撞、回正、重賽、網頁匯入與授權顯示；有骨架者再驗收 rest pose、骨名與動畫。

## 完整資料與重現方式

- [來源登錄表 JSON](research/vehicle-sources.json)：所有本次候選、工具、排除理由及無法連線的搜尋線索。
- [逐檔結構及 SHA-256](research/vehicle-inspection.json)：8 個外部 GLB，加上原創 ION-01 作對照。ION-01 的 `bytes` 僅計 `.gltf` JSON，不含外部 `.bin`。
- [只讀檢查工具](../tools/inspect_car_asset.py)：解析 GLB／glTF 的網格面數、skins、joint 數、動畫及輪子名稱，沒有執行模型內附程式。

```bash
python3 tools/inspect_car_asset.py path/to/car.glb --output report.json
```

`skin_count=0` 表示沒有 glTF 蒙皮綁定；節點動畫仍可能存在。`wheel` 名稱只是查找線索，必須另測旋轉中心。記錄不代表已取得永久下載權、已付款或已完成遊戲整合。後續每取得／修改一個模型，都應新增或更新來源紀錄。
